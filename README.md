# CoActor

CoActor is a Rust runtime for building stateful, addressable actors whose work must be processed sequentially per logical identity.

> **Early development:** CoActor is currently an experimental project. Its APIs, runtime semantics, and architecture may change significantly.

## Goals

CoActor aims to provide a small, explicit runtime for stateful workloads that benefit from:

- stable actor identities;
- lazy activation on first use;
- bounded mailboxes and explicit overload behavior;
- serial command execution within each active actor;
- idle passivation to reclaim resources;
- typed, method-shaped Rust APIs generated by macros;
- clear lifecycle and failure semantics.

The long-term direction includes durable state, ownership fencing, recovery, and migration. These capabilities are being designed incrementally and are not part of the first version.

## First-version scope

The first version is a single-process Rust library built on the consumer's Tokio runtime. It focuses on validating the core in-process actor model:

- actor types registered before runtime startup;
- stable addresses composed from an actor type and actor ID;
- per-key lazy activation;
- bounded per-actor mailboxes;
- non-reentrant, sequential command handling;
- optional asynchronous activation and deactivation hooks;
- idle passivation;
- graceful runtime shutdown;
- structured diagnostics through `tracing`.

Actor state exists only in memory. After passivation, a process exit, or a crash, the actor starts again from empty state.

## Not currently provided

The first version does not provide:

- state persistence, snapshots, journals, or restoration;
- durable mailboxes or durable acknowledgements;
- cross-process or cross-node messaging;
- distributed ownership, fencing, recovery, or migration;
- exactly-once or at-least-once delivery guarantees;
- actor-to-actor calls or actor-scoped timers.

In-process actor uniqueness is scoped to a single CoActor runtime instance and must not be interpreted as a distributed ownership guarantee.
