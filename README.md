# CoActor

CoActor is a Rust runtime for building stateful, addressable actors whose work must be processed sequentially per logical identity.

> **Early development:** CoActor is currently an experimental project. Its APIs, runtime semantics, and architecture may change significantly.

## What CoActor gives you

- stable actor identities from a declared Actor Type and a caller-provided Actor ID;
- lazy activation on first use, bounded mailboxes with explicit overload behavior, and serial, non-reentrant command execution;
- optional asynchronous activation/deactivation hooks, idle passivation, and graceful shutdown;
- typed, method-shaped Rust APIs generated by macros;
- a local mode and an embedded multi-node mode with S3-backed ownership, location-transparent routing for remote-enabled commands, and Owner-side self-fencing.

Actor state exists only in memory. After passivation, a process exit, or a crash, the actor starts again from empty state. CoActor does not currently provide persistence, durable acknowledgements, recovery, or migration.

## Quick start

CoActor is embedded: every process runs a runtime and is a peer node. There is no separate client or server process — a node both hosts Actors and issues calls.

**Node side** — define the Actor, mark cross-node commands with `#[command(remote)]`, and start the runtime:

```rust,no_run
use coactor::{ActorId, CommandContext, RuntimeBuilder, actor,
    cluster::{ClusterConfig, S3OwnershipConfig}};

#[actor(name = "room")]
impl RoomActor {
    #[coactor::command(remote)]
    pub async fn join(&mut self, _ctx: &CommandContext, request: JoinRequest) -> JoinRequest {
        // ...
    }
}

// Every node starts with its own ClusterConfig against the same S3 bucket.
let runtime = RuntimeBuilder::cluster((), ClusterConfig::new(
    "node-a",
    "0.0.0.0:7000".parse().unwrap(),
    "127.0.0.1:7000".parse().unwrap(),
    S3OwnershipConfig::local("coactor", "development", "http://127.0.0.1:9000"),
))
.register::<RoomActor>()
.start()
.await?;
```

**Caller side** — obtain a typed Ref from any node and call; the S3-backed ownership authority routes the call to the current owner, locally or over gRPC:

```rust,no_run
let room_b = node_b.actor_ref::<RoomActor>(ActorId::from("room-7")).unwrap();
room_b.join(JoinRequest { seats: 2 }).await?; // node-b claims ownership, executes locally

let room_a = node_a.actor_ref::<RoomActor>(ActorId::from("room-7")).unwrap();
let reply = room_a.join(JoinRequest { seats: 3 }).await?; // owner is node-b → forwarded over gRPC
assert_eq!(reply.seats, 5);
```

`JoinRequest` is a single `prost::Message + Default` request; the success reply and declared business error must satisfy the same wire decoding requirements. Plain `#[coactor::command]` methods remain local-only even when their Actor Type is registered in cluster mode.

For a single-process walkthrough without S3, run the local counter example:

```console
cargo run -p coactor --example counter
```

For a step-by-step guide — configuration defaults, the actor model, and running multiple cluster nodes — see the [Quick Start](docs/quick-start.md).

## Not currently provided

- state persistence, snapshots, journals, or restoration;
- durable mailboxes or durable acknowledgements;
- durable state recovery after owner failover;
- planned ownership migration or draining;
- exactly-once or at-least-once delivery guarantees;
- actor-to-actor calls or actor-scoped timers.

Local mode scopes actor uniqueness to one runtime instance. Cluster mode coordinates ownership through S3 but still starts a failed-over Actor from empty in-memory state.
