# S3 deployment

CoActor's built-in Coordination Store uses AWS S3 conditional operations for Node Leases and Actor ownership. It stores coordination metadata, not Actor business state.

## Configure the store

```rust
let sdk = aws_config::load_defaults(
    aws_config::BehaviorVersion::latest(),
).await;

let store = S3CoordinationStore::new(
    aws_sdk_s3::Client::new(&sdk),
    "my-bucket",
    "coactor/prod",
)?;
```

Credentials, region, custom endpoints, retries, and HTTP settings are configured through the AWS SDK Client.

Servers need read, list, conditional write, and delete access under the prefix.

CoActor relies on S3 conditional writes for lease and ownership changes. Verify those operations in the intended AWS or S3-compatible environment before production use.

## Cleanup

A crashed process can leave an expired Node Lease object. CoActor ignores expired leases but does not delete them in the background.

Configure S3 Lifecycle expiration for stale Node objects. If Versioning is enabled, also expire noncurrent versions.

Enabling S3 coordination does not make Actions, Events, or Actor state durable.
